# AX의 두 축 2: 개발팀의 에이전틱 엔지니어링

## 독자와 전체 주장

AI 코딩 도구를 막 도입한 일반적인 엔터프라이즈 개발팀이 에이전틱 엔지니어링을 단계적으로 적용하면서 어떤 도구와 관리 체계를 어떤 순서로 갖출지 설명한다. 소프트웨어 팩토리는 한동안 일부 프론티어 팀 중심의 실천이며 지금은 제한적으로 적용 가능하다는 저자의 판단을 밝힌다. 시간이 지나면 모든 개발팀이 이런 방식으로 일하려 할 것이라는 전망을 유지하되, 현재의 전면 도입을 전제로 하지 않는다.

기본 원칙은 DDD의 바운디드 컨텍스트(BC)를 기준으로 한 설명의 완전성이다. 특정 시점의 모노레포 내 BC 부분 또는 멀티레포의 해당 저장소를 격리해도, 그 스냅샷의 코드와 문서만으로 업무의 의미·의도·조건과 구현을 서로 설명할 수 있어야 한다. 외부 위키, 다른 저장소의 내부 구현, 과거 대화나 담당자의 기억이 필수 전제가 되어서는 안 된다. 외부 시스템과 협업하는 데 필요한 계약과 적용 버전도 스냅샷에 포함한다. 이것은 외부 서비스 없이 실행 가능하다는 주장과 구별하며, BC·팀·저장소의 일대일 대응을 가정하지 않는다.

## 뒷받침할 내용

- AX의 두 측면을 구분한다. 이전 엔터프라이즈 AX 글은 주로 비개발자의 업무를 에이전트로 자동화하고 내외부 비즈니스 정보로 내부 프로세스를 개선하는 측면을 다룬다. 이번 글은 개발팀의 에이전틱 엔지니어링 도입을 다룬다. 개발 자동화는 업무 정보·기획문서에 더해 내외부 코드·라이브러리·API·설계·테스트 등 폭넓은 정보를 가져와 엔드유저에게 전달할 코드를 만든다. 업무 규칙이 같아도 코드·의존성·구현 상태가 계속 변하므로 일반 업무 AX보다 맥락과 검증 대상의 변화가 잦고, 안정적으로 동작하는 코드를 만드는 것이 핵심이다. 전자의 업무 정보가 정적이거나 검증이 불필요하다는 뜻으로 쓰지 않는다.
- 사용자가 제공한 사내 개발 지식 보고서에서 도구의 역할 분리, 짧고 팀이 소유한 지침, 효과 검증과 선택적 도구 사용을 참고한다. 비공개 시스템명·수치·링크는 공개용 블로그 초안에 옮기지 않고 팀 운영 제안으로 일반화한다. 사내 조사 범위를 전사 부재의 증거로 바꾸지 않는다.
- 공개 alps-writer-plugins의 의도와 철학을 실제 문서에서 확인해 설명한다. PRD는 기획 입력이며 인계 후 구현 계약은 ADR이 소유한다. 온톨로지는 업무 흐름·책임·개념·관계, ADR은 기능 조건·정확한 요구값·설계 이유, 코드는 구현과 실행 근거를 맡는다. 상위 계층에 하위 파일 경로나 호출 그래프를 복제하지 않는다.
- 온톨로지는 필요한 비즈니스 정보를 빠르게 좁혀 읽는 수단이다. 가벼운 BC 책임·핵심 업무·협업 지식과 내부 흐름을 분리하고, 이미 대상이 알려졌다면 그 지점에서 시작한다. 전체 모델 구축이나 그래프 도입을 초기 조건으로 강요하지 않는다.
- 코드는 직접 키워드·심볼로 찾거나 MCP를 통해 내부 코드의 키워드·유사도 검색을 사용한다. 코드 그래프는 관계 추적의 실제 병목이 있을 때 선택하며 성숙도 필수 단계로 두지 않는다.
- 초기 사용자를 위해 코드를 미리 AI로 정리하고 근거와 함께 질문에 답하는 시스템을 다룬다. 생성 문서는 특정 코드 버전의 학습·탐색 자료로 운영하고, 팀의 승인된 요구사항이나 매번 주입하는 지침과 혼동하지 않는다. 갱신·권한·누락·담당자·평가를 구체화한다.
- 이전 컨텍스트 엔지니어링, 외치는 코드, 하네스, 소프트웨어 팩토리 글을 이어받되, 이 글의 독자 질문인 개발팀의 도구 구성과 관리에 집중한다. 단계별 시작 조건·담당자·절차·산출물·완료 기준 및 실패 대응을 제시한다. 도구와 문서 자체도 버전·변경 검토·평가·회수 대상으로 관리한다.

## 문체와 산출물

본문의 다이어그램을 적극 활용한다. 제공된 HTML의 지식 유형별 연결과 후보 지식의 검토·공유 흐름을 참고해, BC 스냅샷·계층별 인계·코드 설명의 검토·질문별 도구 선택·실행 검증·개발 환경 개선을 시각화한다. 비공개 사례의 명칭과 수치는 옮기지 않고, 그림의 관계와 조건은 본문의 제안과 일치시킨다. 한국어·영어 다이어그램도 대응시킨다.

엔터프라이즈 AX 글과 함께 「AX의 두 축」 시리즈로 구성한다. 1편은 「AX의 두 축 1: 에이전트로 업무 자동화하기」, 이 글인 2편은 「AX의 두 축 2: 개발팀에 에이전틱 엔지니어링 도입하기」로 제목을 정한다. 시리즈의 두 편은 업무 자동화와 개발 자동화라는 AX의 두 측면을 다룬다. 2편 내부의 실천 순서는 단계적이지만 두 편 자체를 성숙도의 선후 단계로 표현하지 않는다. 기존 파일·URL 식별자는 유지한다.

런북 성격의 기술 블로그 글로, 짧고 자연스러운 문단과 업무 예시로 설명한다. 저자의 입장은 직접 드러내되 경험·성과를 지어내지 않는다. 공개 플러그인의 주문·결제 예시는 학습용 예시로 다루고 실제 서비스 구현으로 소개하지 않는다. 한국어 원고와 완전한 영어 대응본을 검토한다. 사용자가 두 편의 번역 누락 수정과 게시를 요청했으므로, 검토 후 두 언어의 발행·커밋·푸시·실제 게시 확인까지 수행한다.
