# 블로그 초안 자체 검토

## 검토 기준

독자의 질문은 더 좋은 모델이 실제 업무를 끝내려면 무엇이 더 필요한가이다. 글의 답은 모델이 필요한 기능을 직접 사용할 수 있는 앱과 실행 환경이 필요하며, 도구 제작의 속도와 비용이 달라져도 자동화할 일의 범위가 넓어질 수 있다는 것이다. 주니어 개발자와 AI 활용에 관심 있는 독자를 위한 개인 경험 중심의 기술 에세이로 작성했다.

사용자가 제공한 앱 제작·마이그레이션 경험은 본인의 경험으로 유지했다. 공식 블렌더 사례와 개인 경험을 구분하고, MCP만으로 모델 성능이나 자동화 성공을 설명하지 않았다. 속도와 비용에 관한 후반부는 전망으로 서술했다.

## 2차 검토와 수정

수정한 결말에 “이번에도 안 되면 직접 하거나 포기할 생각”이라는 표현이 생겼다. 사용자는 전부 맡길 수 없으면 하지 않을 생각이었다고 명시했으므로, 행동의 조건을 바꾸는 Medium 문제로 판단했다. “이번에도 전부 맡길 수 없으면 안 할 생각”으로 바로잡았다.

## 최종 전체 검토

제목, 영문 excerpt, TL;DR, 도입, 본문 5개 절, 도식 문구, 결말과 각주를 다시 읽었다.

- 문장의 자연스러움: 뜻을 바꾸는 부정·조건·수치 변화나 의미 있게 어색한 문장을 찾지 않았다.
- 문장·문단 연결: 블렌더 사례에서 개인 경험, 기능 접근, 모델과 도구의 관계, 속도·비용 전망으로 이어진다.
- 주제 전달과 구성: 모델의 능력을 사용할 수 있는 환경이라는 주제를 유지하며, 결론의 범위를 개인 경험과 전망에 맞췄다.
- 구체성·근거·설명력: 기존 Swift 앱, 5일간의 Python→Go 이전, 첫 버전 3일과 추가 조정 3일을 유지했다. 자막 시간 수정은 설명용 예시로 제시했다. API, MCP와 headless의 의미를 본문에서 설명했다.
- AI Slop: 반복된 결말과 추상적 비용 문장을 수정했다. 측정하지 않은 속도 개선율이나 가상의 개인 경험을 추가하지 않았다.
- 저자 문체·스타일: 하기 싫은 일에서 출발하는 동기, 짧은 문단, 경험에 따른 의견, 구체적인 앱 제작 과정을 유지했다.

남은 문제: High 0 / Medium 0 / Low 0.

## 출처 확인

내장 웹 도구에서 결과를 받지 못해 DuckDuckGo MCP의 페이지 조회로 다음 원문을 확인했다.

- OpenAI, Architectural visualization with Astra: `bpy`, 렌더링 결과 검토와 수정, 백그라운드 Python 실행, 화면 조작, 카메라 영상 제작을 확인했다.
- Model Context Protocol 공식 소개: 외부 시스템의 도구와 데이터를 연결하는 규약임을 확인했다.
- ahujasid/blender-mcp README: 커뮤니티 도구임을 구분하고 장면 조회, 물체·재질 수정, Python 실행 기능을 확인했다.
- 내부 링크 두 개는 원문 파일 존재, 공개 상태와 `.html` 경로를 확인했다.

## 파일 검증 및 한계

- 해당 초안의 `post-lint.sh`: 통과.
- `git diff --check`: 통과. 새 파일의 주요 형식은 별도 검사했다.
- 필수 front matter 7개, 각주 정의·참조 대응, 내부 링크 대상, Liquid raw 및 Mermaid fence 균형: 통과.
- HTML의 문서 변환, 각주 앵커, 중복 ID, 9개 절 제목 및 Mermaid 도식과 원문 영역: 정적 검사 통과.
- Jekyll 빌드: 필요한 Bundler 2.6.8이 시스템 Ruby 환경에 없어 실행하지 못했다.
- HTML 화면 검증: 브라우저 보안 정책이 로컬 파일 URL 열기를 차단했다. 다른 브라우저나 우회 경로로 재시도하지 않았다. 따라서 글꼴·줄바꿈과 Mermaid 렌더링의 시각적 검증은 미완료다.
- HTML은 읽기용 별도 미리보기이며, 실제 사이트 테마를 빌드한 결과가 아니다. 도식 렌더링은 사이트와 같은 Mermaid 10 CDN에 의존한다.
- 원고는 `_drafts/`에 `publish: false`로 저장했다. 커밋·푸시·게시하지 않았다.

## 프로젝트 이름 반영 후 재검토

사용자가 세 사례의 이름을 직접 확인해주어 원고와 HTML 미리보기에 반영했다.

- Scribird: 5.6 sol이 약 3일 동안 스스로 작업해서 만든 Swift 앱. Storybird를 만들 때 사용한 기존 코드의 이름을 명시했다.
- PixelBankStudio: Python에서 Go로 옮기는 작업 전체를 맡겼고, 에이전트가 약 5일 동안 스스로 진행해 마친 원샷 마이그레이션 사례. 사용자가 모델명을 따로 확인하지 않았으므로 특정 모델명을 추가하지 않았다.
- Storybird: 이번 영상 제작 앱. Astra가 첫 버전을 만드는 데 약 3일, 실제 사용하며 다듬는 데 추가 약 3일이 걸렸다는 구분을 유지했다. MCP와 도식의 앱 이름도 맞췄다.

앞서 읽은 두 최근 글과 두 2017년 글의 문체 기준을 재사용해, 변경 후 원고 전체를 다시 읽었다. 문장의 자연스러움과 문단 연결에는 추가 수정할 문제가 없었다. 주제와 구성에서는 앞선 두 경험이 Storybird 제작을 맡길 수 있었던 이유로 이어진다. 구체성과 근거는 사용자가 제공한 이름·기간·작업 내용에 맞으며, 새로운 앱 기능이나 성과를 추가하지 않았다. AI Slop과 저자 문체 검토에서도 추가로 고칠 문제를 찾지 않았다.

추가 발견 사항 없음. 최종 자체 검토 High 0 / Medium 0 / Low 0.

초안 lint와 공백 검사, HTML의 세 프로젝트 이름 및 각주 앵커 대응을 다시 확인해 통과했다. 기존 Jekyll 빌드와 브라우저 화면 검증의 제한은 그대로이며, 우회하거나 검증 완료로 표시하지 않았다.

## 회사 인증 과정과 자동화 동기 반영 후 재검토

사용자가 제공한 회사 인증 과정의 배경을 새 2절에 추가했다. 독자의 질문과 글의 답은 그대로 유지하면서, 영상 제작을 맡긴 이유가 귀찮다는 감정에만 머물지 않도록 업무 구조에 관한 의견을 연결했다.

반영한 내용:

- SA를 처음 등장하는 문장에서 풀어 설명했다. 고객에게 코드를 전달하기 위한 인증 과정과, 실제 구현 및 지정된 템플릿의 데모 영상 제출이라는 마지막 과제를 사용자 설명대로 담았다.
- 기간에 맞추려다 고객 요구사항을 지나치게 줄이고 주변 맥락을 제외하게 되기 쉽다는 우려를 저자의 판단으로 제시했다.
- 외부 코드 전달에 필요한 보안 점검, 고객의 코드 이해와 배포를 위한 문서·발표자료, 이 일을 SA가 기한 안에 해야 하는 부담을 유지했다.
- “시장 역행”이라는 단정은 모델을 쓰며 겪은 변화와 인증이 강조하는 방향이 어긋난다고 느꼈다는 의견으로 다듬었다.
- “누구나 구현할 수 있다”는 보편적 주장 대신 저자가 경험한, 요구사항과 작업 방법이 정해진 구현에 대한 관찰로 썼다.
- 고객의 직접 구현을 돕는다는 입장을 남겼다. 고객이 직접 만들면 보안 검토가 전부 사라진다는 표현은 쓰지 않았고, 고객의 환경과 검토 절차에서 개발하면 외부 결과물 전달에 따른 별도 준비를 줄일 수 있다는 주장으로 범위를 구체화했다.
- 새 2절은 전달 작업의 자동화 동기로 끝내고, 기존 Scribird·PixelBankStudio·Storybird 경험으로 이어지게 했다. 기존 절 번호와 HTML 미리보기도 맞췄다.

문체 참고는 앞선 네 글을 재사용했다. 추가로 `_posts/2026-09-03-developers-to-internal-fde.md` 전체를 읽어, 코드 작성 이후의 업무 맥락과 전달·운영 부담에 관한 기존 저자의 입장을 확인했다. 이번 글에 별도의 FDE 논의를 덧붙이지는 않았다.

최신 원고 전체를 여섯 축으로 재검토했다. 문장에서는 SA를 설명하고 강한 표현을 구체적인 업무 부담으로 풀었다. 문단 연결과 구성에서는 새 인증 배경을 구현 경험 앞에 두었으며, 블렌더·실행 환경·속도와 비용이라는 기존 주제를 유지했다. 근거는 사용자의 직접 경험과 의견으로 구분했고 프로그램의 명칭이나 내부 정책을 추측하지 않았다. AI Slop과 저자 문체에서는 추상적인 회사 비판이나 반복적인 유감 표명 없이, 왜 이 일을 자동화하려 했는지에 필요한 내용을 남겼다.

추가 수정이 필요한 발견 사항 없음. 최종 자체 검토 High 0 / Medium 0 / Low 0.

원고 lint, 공백 검사, 1~6절 번호, 미발행 상태, 각주 대응, 내부 링크 대상, HTML의 10개 절 제목 및 앵커 대응 검사를 통과했다. 전체 사이트 빌드와 시각 검증의 기존 제한은 유지된다.

## 2절 첫 문장에 대한 사용자 피드백 반영

직전 검토에서 2절의 연결 문제를 놓쳤다. “영상 제작을 자동화하려던 데는 업무에 대한 생각도 조금 섞여 있었다”는 문장이 어떤 영상을 왜 제출해야 하는지 설명하기 전에 동기를 예고했고, “업무에 대한 생각”도 구체적인 정보를 주지 않았다.

최신 자체 검토의 남은 문제는 High 0 / Medium 0 / Low 0이다. 이 결과는 직전 검토에서 놓친 문제가 없었다는 뜻이 아니다.
